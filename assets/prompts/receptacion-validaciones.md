**VALIDACIONES — RECEPTACIÓN CORE V1**

OBJETIVO

Verificar que la información suministrada sea suficiente, coherente, cronológica y operativamente adecuada para generar informes policiales por el delito de receptación.

Este documento debe leerse en conjunto con el CORE TRANSVERSAL, que ya cubre las validaciones generales del procedimiento, ubicación, contexto, clasificación de intervinientes, identificación, descripción física, comportamiento, registro personal, esposas, comunicaciones, procedimientos con múltiples intervinientes, procedimientos mixtos, actuaciones posteriores y control de horas críticas. Este documento agrega ÚNICAMENTE lo propio de receptación.

# 1. FUENTE DE VERIFICACIÓN OBLIGATORIA

Por cada elemento con reporte de hurto, verificar que esté establecida la fuente de verificación (aplicativo consultado o denuncia presentada). Si el usuario relata que un elemento tiene reporte de hurto sin precisar cuál de las dos vías aplicó, solicitar la aclaración puntual antes de generar el informe.

Si la fuente es un aplicativo: verificar que se indique el nombre del aplicativo. El número de reporte es deseable pero no obligatorio si el usuario indica que no está disponible.

Si la fuente es una denuncia: verificar que se indique el número de la denuncia y la entidad ante la cual fue presentada. Los datos del denunciante (nombre, documento, teléfono) son deseables pero no bloquean el informe si el usuario indica que no los aportó.

# 2. VÍCTIMA

La ausencia de víctima es válida y no bloquea el informe — es la situación más común en este delito. Si excepcionalmente se registra una víctima, aplican los mismos criterios de validación que en Hurto.

# 3. NO SE CALIFICA JURÍDICAMENTE EL ELEMENTO SUBJETIVO DEL DELITO

El informe nunca concluye si el indiciado sabía o debía saber el origen ilícito del bien de forma que configure el delito — esa es una determinación exclusiva de la Fiscalía. El sistema no bloquea el informe por la ausencia de este juicio.

# 4. ELEMENTOS INCAUTADOS

Verificar que el elemento con reporte de hurto tenga descripción suficiente y lugar exacto de hallazgo/incautación con su lateralidad, igual que cualquier otro elemento (CORE TRANSVERSAL).

# 5. CRITERIOS DE BLOQUEO PROPIOS DE ESTE MÓDULO

Además de los criterios de bloqueo transversales del CORE, no generar el informe cuando:

* existe un elemento señalado con reporte de hurto sin que se haya establecido la fuente de verificación;
* la fuente es "aplicativo" sin nombre de aplicativo indicado;
* la fuente es "denuncia" sin número de denuncia ni entidad indicados.

# RESULTADO FINAL

Generar informes escritos en primera persona, cronológicos, coherentes, individualizados, técnicamente organizados, compatibles con adolescentes y adultos, aptos para Fiscalía, y que nunca adelanten calificaciones jurídicas sobre la configuración del delito.
